# 01 · 产品定位与范围

## 定位

flash-dns 是一个面向自动化的 DNS 记录管理工具：将项目上下文和命名规则转换为完整域名，再通过服务商适配器查询、创建、更新和删除记录。

它同时提供终端入口和程序接口。普通用户使用 CLI；flash-tunnel、CI 或其他工具通过核心库组合业务流程。

“DNS 解析”在本项目中指配置权威 DNS 记录，不是实现递归解析器或运行 DNS 服务器。

## 用户场景

| 场景 | 命名输入 | 记录目标 | 生命周期管理者 |
| --- | --- | --- | --- |
| 持久站点 | 项目名、命名空间 | A / AAAA / CNAME | 站点工具或用户 |
| 临时预览 | 项目名、分支、会话标识 | Tunnel CNAME 等 | flash-tunnel 等调用方 |
| CI 自动化 | 仓库名、稳定项目标识、流水线上下文 | 外部传入 | CI 或部署系统 |
| 自定义业务 | 显式 hostname 或规则变量 | 外部传入 | SDK 使用方 |

项目实例：

```text
项目名：@org-name/project-name
标准化：org-name-project-name
模板：{project}.slidev.acewill.dev
结果：org-name-project-name.slidev.acewill.dev
Zone：acewill.dev
```

这里的 `slidev` 是用户配置中的普通命名空间，不是工具内建概念。

## 负责的工作

- 发现项目名和上下文，应用显式配置的命名规则。
- 校验项目标签、完整域名、Zone 边界以及适配器能力。
- 展示预期变更，将记录协调到期望状态。
- 区分本工具管理的记录和已有外部记录，避免覆盖无关资源。
- 暴露一致的结果、错误码、取消和日志接口。
- 封装服务商差异，允许后续适配器扩展。

## 职责之外

- Slidev、Vite 或其他应用的识别、构建与启动。
- 创建、启动、监控或删除 Cloudflare Tunnel。
- SSH 登录、rsync、静态文件发布和版本回滚。
- Nginx 配置、反向代理和应用健康检查。
- HTTPS 证书申请、网站访问控制或隐藏源站 IP。
- 自行判断调用方何时结束会话并清理 DNS。

CLI 进程退出后，DNS 记录继续存在。需要清理时，由用户执行命令或由 SDK 调用方显式删除。

## 首版范围（建议）

- Cloudflare 适配器。
- A、AAAA、CNAME、TXT 的单条记录操作和查询。
- 项目名标准化、模板生成、显式 hostname。
- `init`、`plan`、`ensure`、`list`、`remove`、`doctor`。
- 配置加载、结构化输出、幂等、冲突检测和归属检查。
- SDK 与 CLI 的离线测试及打包验证。

首版不实现 RRset 全量同步、批量事务、多账户调度和后台管理服务。`ensure` 针对一条受管记录，不表示“让整个域名只剩下这一条记录”。

## 成功标准

1. CLI 可以按配置生成正确域名并创建记录。
2. 相同配置重复执行不会无故重建记录。
3. 外部记录或其他 owner 的记录不会被默认覆盖。
4. SDK 不依赖 CLI、终端 UI 或 Cloudflare 专有实现。
5. flash-tunnel 可以通过少量桥接代码接入，无需改变其隧道生命周期。
6. 新增服务商时，主要增加适配器及契约测试，无需重写核心协调流程。
