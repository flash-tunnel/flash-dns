# 05 · 幂等、归属与生命周期

## 资源归属

owner 至少包含 application 和 id：

```text
持久站点：application = deploy-system，id = gitlab:<stable-project-id>
临时预览：application = flash-tunnel，id = <session-id>
```

owner 与记录名称分离。工具标记只表示谁管理记录，不是权限认证或防篡改签名；真正访问权限由服务商凭据控制。

CLI 托管的记录使用显式 project.id 派生稳定 owner。`init` 可生成并持久化 ID，但已存在项目的 plan/list 不应偷偷改配置或随机创建身份。SDK 使用方可直接传 owner。

Cloudflare 记录元数据建议存放版本化标记，如 `flash-dns:v1:<encoded-owner>`，最终编码需考虑字段长度、合法字符和已有用户备注保留。不能仅判断“含 flash-dns 前缀”就允许覆盖。

## 协调步骤

```text
解析配置与上下文
  → 生成并校验 hostname
  → 验证适配器能力
  → 解析 Zone，读取同名相关记录
  → 判断归属和冲突
  → 生成 create / update / noop / conflict 计划
  → 执行前重新检查
  → 按 ID 创建或更新
  → 读取 API 状态，返回实际结果
```

`plan` 只读取和计算，不能写 DNS、生成云资源或注册退出清理。`ensure` 默认基于当前状态重新计算，不假定此前打印的计划仍然有效。

## 行为表

| 当前状态 | 默认行为 |
| --- | --- |
| 无相关记录 | 创建并写入 owner |
| 同 owner，期望字段一致 | noop，保留记录 ID |
| 同 owner，目标或显式选项变化 | 原位更新并校验结果 |
| 同 owner，匹配到多个无法区分的候选 | AMBIGUOUS_RECORD，要求明确 ID |
| 已有记录无 owner，即使内容一致 | RECORD_CONFLICT，不隐式接管 |
| 名称相同但 owner 不同 | OWNERSHIP_MISMATCH |
| 服务商不支持要求的选项 | CAPABILITY_UNSUPPORTED |

对多值类型，不把“同名”直接等同于冲突：同名 A、AAAA、TXT 可有其他用途。只管理明确归属和明确选择的记录，不清空整个记录集。

CNAME 及其他类型之间的共存限制由适配器准确校验。首版不做跨类型自动删除与重建；需要迁移类型时明确报错，由调用方组织迁移。

首版不提供全局 `--overwrite`。接管外部资源或修改 owner 作为后续独立操作设计，要求明确记录 ID、原状态和变更预览。

## 更新语义

- 对比规范化后的记录值，减少尾点、大小写等差异造成的无效更新。
- 只改变显式要求的字段和必要的归属字段。
- 保留无关元数据；代理和 TTL 按适配器约束处理。
- 更新失败时保留旧记录，不通过删除旧记录来制造重试机会。
- 不为“恢复”而盲目写回旧快照，避免覆盖外部并发变更。

## 删除语义

SDK 的 ensure 结果返回可用于删除的 record ref，包含 provider、zoneId、recordId 和 owner。删除前重新读取并核对当前归属，必要时核对目标快照。

- 指定记录已经不存在：返回 already-absent，视为幂等成功。
- 当前 owner 与预期不同：拒绝删除。
- 同名但不同 ID 的新记录：不因为 hostname 相同就删除它。
- 通过名称删除时先 plan，目标不唯一则拒绝执行。
- CLI 交互环境展示目标并确认；非交互环境要求显式 `--yes` 和明确选择器，不能停下来等待输入。

进程退出、SIGINT、SIGTERM 不触发隐式 DNS 删除。调用方需要的退出清理由调用方实现。

## 并发与不确定结果

DNS API 不一定提供跨请求锁或原子 compare-and-swap。执行前检查只能缩小竞态窗口，不能宣称完全避免外部竞争。

- 核心库保证单次流程内部顺序；同一管理器可按资源键串行执行写操作。
- 跨进程、跨机器协调由调用方提供，例如 CI 部署锁；后续再考虑可插拔锁。
- 创建请求超时可能已成功。先重新查询归属和期望值，再决定是否重试，避免重复创建。
- 429 遵守 Retry-After；网络和 5xx 采用有上限的退避。取消、权限、冲突和参数错误不盲目重试。
- 状态发生变化则重新计算或返回 PLAN_STALE；不继续使用过期计划进行破坏性操作。

## 完成的含义

操作成功表示服务商 API 中的记录达到期望状态，不代表所有递归解析器缓存已刷新，更不代表 HTTPS 或应用已可访问。

Cloudflare 橙云可能改变公网查询结果，不能用“公网 A 等于源站 IP”作为统一成功条件。第一版以服务商状态确认作为完成依据。
